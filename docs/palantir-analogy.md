# 팔란티어 유추 — coral 은 무엇의 일반화인가

> 사용자 정식화 (2026-08-20 세미나): "결국 우리가 하는 것이 팔란티어가
> 온톨로지 만들고 FDE 하는 것의 일반화 버전 아닌가?"
> 판정: **서비스 트랙에 한해 정확한 분류. 비전 트랙은 프레임 밖.**
> 용도: 포지셔닝·투자 설명 재료. 팔란티어 세부는 공개 자료 기반 (확신도 중).

---

## 1. 대응표 — 맞는 절반

| 팔란티어 | coral |
|---|---|
| 온톨로지 = 조직 운영 현실의 시맨틱 레이어. 지속·복리 자산 | 정본 온톨로지 = 검증 지식의 신규 안정층. 지속·복리 자산 |
| **FDE(Forward Deployed Engineer)** — 도메인 전문가 옆에 앉아 암묵지를 끄집어내 구조로 만드는 **고용 노동** | **사용자 자신** — 문답·증분·반증·실측으로 자기 암묵지를 구조에 흘려 넣는 **시장 참여자** |
| 기저 기술(LLM 포함)은 교체 가능 부품. 해자는 축적층 | 동일 — "스케일은 남의 전쟁, 우리는 그 위에 누적되는 것을 소유한다" |
| 운영 결과로 검증 (배치 후 수율이 올랐는가) | 외부 실측 닻 (`verification.py`) |
| 반복 배치의 패턴이 제품으로 굳음 (Gotham → Foundry) | 폴립의 검증 통과가 정본으로 굳음 (승격) |

핵심 동형: FDE 는 **§B5 "은폐된 편집 노동"의 기업 소프트웨어 버전**이다.
랩이 큐레이터·라벨러를 고용하듯, 팔란티어는 지식 추출자를 고용한다.

## 2. 일반화의 내용 — 세 축

coral 이 팔란티어 모델에서 바꾸는 것은 정확히 §B5 가 요구한 "은폐된 편집
판단의 외재화 + 결정권 분산"이다:

| 축 | 팔란티어 | coral |
|---|---|---|
| **누가 포획하는가** | 고용된 FDE (급여) | 스테이킹·배당 유인의 시장 참여자 — **노동의 시장화** |
| **누가 판정하는가** | FDE-고객 내부 합의 | 공개된 결정론 함수 + 시장 + 실측 닻 — **판정의 제도화** |
| **누가 소유하는가** | 고객사별 사일로 (digital twin, 조직 간 비공유) | 승격으로 자라는 공유 정본 — **축적의 탈사일로화** |

부수 효과: 팔란티어에서 지식의 원천(고객사 도메인 전문가)은 보상받지 않는다.
coral 은 기여 비례 배당으로 그 가치를 원천에 되돌린다 — "가치: 데이터 무상
수취 → 기여 정산"(방향 종합의 세 번째 독점 전복).

**뜻밖의 선물**: 팔란티어의 시가총액은 "동결 기저 위의 온톨로지 + 인간 암묵지
추출 노동"이 얼마나 값비싸고 방어 가능한 자산인지에 대한 **시장의 실증**이다.
"그런 게 팔리냐"는 질문에는 이미 답이 존재한다.

## 3. 깨지는 절반 — 차이점 병기 (프로토콜 의무)

**① 온톨로지의 존재론이 다르다.**
팔란티어 온톨로지는 *운영적*이다 — 객체·링크에 **액션**이 묶여 조직 시스템에
되쓰기(write-back)한다. "무엇이 있고 무엇을 할 수 있나". coral 온톨로지는
*인식적*이다 — "무엇이 참인가". 그래서 팔란티어에는 coral 의 핵심 기관이
없다: 스테이킹도, 손상 판정도, 잠복/부활도 없다. **필요가 없기 때문이다 —
닫힌 조직 안에서는 고용 계약과 접근 통제가 유인합치를 대체한다.** coral 이
면역계를 지어야 하는 이유는 열린 적대 환경으로 나갔기 때문이고, 그것이
일반화의 세금이다.

**② 비전 트랙은 프레임 밖이다.**
팔란티어는 심볼릭 온톨로지 + 동결 기저에서 *멈춘다* — coral 용어로 승격
(a)경로까지가 전부다. (b)경로(검증 지식의 신경 체화), "살아있음" 축은 이
유추가 닿지 않는 곳이며, 그것이 이 프로젝트 정체성의 절반이다.

기타: FDE 는 지식 추출 외에 통합 배관(데이터 파이프라인) 노동을 포함한다 —
coral 에 대응물 없음. 팔란티어의 계약·보안 모델(기밀 취급 인가 등)도 유추
범위 밖.

## 4. 전략 교훈 3

1. **콜드스타트의 답 — 초기에는 우리가 FDE 다.** 팔란티어도 시장으로 시작하지
   않았다. 소수 고객에 깊이 박혀(사실상 창업자들이 FDE) 첫 온톨로지를 손으로
   팠다. KnowledgeNet 의 B2B 피벗("한 팀·한 불량")이 정확히 이 수순이다.
   첫 정본은 시장이 아니라 우리가 판다 — 시장은 그다음에 넘겨받는다.
2. **일반화 버전 = 팔란티어가 구조적으로 못 가는 곳.** 조직 경계 밖의 지식,
   조직에 속하지 않은 개인 전문가, 조직 간에 공유되면 모두가 이득인
   비경쟁 지식. 포지셔닝은 "팔란티어 대체"가 아니라 **"그 모델이 못 여는
   시장"**이다.
3. **사일로의 이유를 존중할 것.** 팔란티어가 사일로를 유지하는 건 무능이
   아니라 고객 기밀 때문이다. 공유 정본은 기밀 지식을 담을 수 없다 — 도메인
   선택과 "공유의 명시성"(promotion-gate-spec §7 열린 결정)에 직접 걸리는
   제약이다.

## 5. 중력 경계 ⚠

이 분류는 정확해서 위험하다. "팔란티어의 일반화"가 **"온톨로지 컨설팅 B2B
회사를 하자"로 미끄러지는 순간** — (b)경로를 버리고 (a)경로 사업만 남기는
순간 — 중력 1(비전의 하이브리드 축소)의 재발이다.

정확한 관계는 한 줄로 잡아둔다:

> **팔란티어 모델은 우리의 서비스 트랙이 버티는 방법의 실증이고,
> 우리의 비전 트랙은 그 프레임이 끝나는 지점에서 시작한다.**
